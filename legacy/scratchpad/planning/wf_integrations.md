## 1. Public ATS job APIs

**Bottom line:** every ATS below has a public, keyless read API. None has an apply API a candidate can use. Each apply endpoint needs the *employer's* secret key, and the hosted forms use bot detection. So Agent HQ should: discover through the APIs, prepare materials automatically, then open `applyUrl`/`absolute_url` so a human submits.

### Greenhouse (Job Board API)
Source: https://docs.greenhouse.io/job-board.html (it moved from developers.greenhouse.io)
- **List jobs:** `GET https://boards-api.greenhouse.io/v1/boards/{board_token}/jobs?content=true`
  - `content=true` adds the description, departments and offices.
  - **[live]** Keys returned: `jobs[]`, `meta`. Each job has `id, title, absolute_url, location, updated_at, first_published, content, departments, offices, metadata, requisition_id, application_deadline, data_compliance, company_name, language`.
  - `content` is HTML-entity-escaped, so unescape it before parsing.
- **Job detail:** `GET .../boards/{board_token}/jobs/{job_id}?questions=true&pay_transparency=true`
- **Other reads:** `GET .../departments[/{id}]` and `GET .../offices[/{id}]`
- **Apply:** `POST .../boards/{board_token}/jobs/{id}`
  - Needs HTTP Basic Auth with the employer's API key as the username.
  - The docs say form posts "should be proxied by your own servers" so the key isn't exposed. Candidates can't use it.
- **Rate limits:** none documented for the Job Board API.
- **Hosted form:** Google invisible reCAPTCHA, with spam sensitivity set per job board. https://support.greenhouse.io/hc/en-us/articles/115005448066-Invisible-reCAPTCHA

### Lever (Postings API v0)
Source: https://github.com/lever/postings-api
- **List:** `GET https://api.lever.co/v0/postings/{site}?mode=json&skip=&limit=&location=&commitment=&team=&department=&level=`
  - EU accounts use `https://api.eu.lever.co/v0/postings/{site}`.
- **Detail:** `GET /v0/postings/{site}/{posting_id}`
- **Fields:** `id, text, categories{location,commitment,team,department}, descriptionPlain, lists[], hostedUrl, applyUrl, workplaceType, salaryRange`
- **Apply:** `POST /v0/postings/{site}/{posting_id}?key=APIKEY`
  - The key is generated by the employer's Super Admin.
  - More than 2 POSTs per second returns `429 TOO_MANY_REQUESTS`. Name and email are required.
- **Hosted form:** hCaptcha is shown to suspicious users. https://help.lever.co/hc/en-us/articles/20087243347741-Configuring-your-Lever-application-form

### Ashby
Source: https://developers.ashbyhq.com/docs/public-job-posting-api
- **List:** `GET https://api.ashbyhq.com/posting-api/job-board/{JOB_BOARD_NAME}?includeCompensation=true`
- **Fields:** `title, location, secondaryLocations, department, team, isListed, isRemote, workplaceType, descriptionHtml, descriptionPlain, publishedAt, employmentType, jobUrl, applyUrl`
- **Compensation fields:** `compensationTierSummary, scrapeableCompensationSalarySummary, compensationTiers[], summaryComponents[]`
- **Rate limits:** not documented.
- **Apply:** `POST https://api.ashbyhq.com/applicationForm.submit`
  - Needs Basic Auth with an API key that has `candidatesWrite` permission.
  - It is meant for employers building their own careers pages. https://developers.ashbyhq.com/reference/applicationformsubmit
- **Hosted form:** spam protection with Strict / Permissive / Less Permissive / Off levels. https://docs.ashbyhq.com/job-board-application-spam-protection
  - Community reports say Playwright or webdriver sessions get "flagged as possible spam" through reCAPTCHA scoring. https://github.com/career-ops-hq/career-ops/issues/4269

### SmartRecruiters
- **List:** `GET https://api.smartrecruiters.com/v1/companies/{companyIdentifier}/postings?q=&limit=&offset=&country=&region=&city=&department=&language=`
- **Detail:** `GET .../postings/{postingId}`
- Source: https://developers.smartrecruiters.com/docs/endpoints.md
- **Auth caveat:** the overview says the Posting API "supports both API Key and OAuth 2.0" (scope `internal_postings_read`). Public company postings are commonly reachable without a key, but test before relying on it. https://developers.smartrecruiters.com/docs/posting-api
- **Apply:** `POST /postings/{uuid}/candidates`
  - Needs the `X-SmartToken` header (a customer or partner credential).
  - Required fields are firstName, lastName and email. https://developers.smartrecruiters.com/docs/post-an-application.md
- **Rate limits:** https://developers.smartrecruiters.com/docs/rate-limiting.md and `/docs/throttling-policies.md`

### Workable
- **Documented, no auth:**
  - `GET https://www.workable.com/api/accounts/{subdomain}?details=true`
  - `.../locations` and `.../departments`
  - Source: https://help.workable.com/hc/en-us/articles/115012771647
- **Widget JSON (used by the community, not formally documented):** `GET https://apply.workable.com/api/v1/widget/accounts/{subdomain}`. It returns every job in one response with no filtering. https://dev.to/zsevic/integration-with-workable-public-jobs-api-3nk4
- **Full API:** `GET https://{subdomain}.workable.com/spi/v3/jobs` needs a Bearer token with `r_jobs` scope. Creating candidates needs `w_candidates`, which is employer-only.

### Recruitee (Careers Site API)
- **List:** `GET https://{company}.recruitee.com/api/offers/?department=&tag=`
- **Detail:** `GET /api/offers/{id}`
- **Fields:** `id, slug, title, description, requirements, remote/on_site/hybrid, locations[], salary{min,max,period,currency}, open_questions[], careers_url, careers_apply_url`. https://docs.recruitee.com/reference/offers
- **Apply:** `POST /api/offers/{offer_slug}/candidates`. Name and email are always required; phone and CV are required by default. https://docs.recruitee.com/reference/offersoffer_idcandidates
- **Deadline:** from **10 Feb 2027**, every Careers Site API call, including the GET `/offers` reads, needs the header `X-Careers-Sites-Token`. Calls without it get 401. That token is per-employer user. The XML feed and jobs widget are not covered by it. https://docs.recruitee.com/reference/authentication-1
- Plan a fallback before then.

## 2. Remote job feeds

### Remotive
- **Endpoints:** `GET https://remotive.com/api/remote-jobs?category=&company_name=&search=&limit=`; categories at `/api/remote-jobs/categories`
- **[live] Fields:** `id, url, title, company_name, company_logo, category, tags, job_type, publication_date, candidate_required_location, salary, description`

## 4. Gmail API for a local desktop app

- **Setup:**
  - `pip install google-api-python-client google-auth-httplib2 google-auth-oauthlib`
  - Create an OAuth client with **Application type = Desktop app** and save it as `credentials.json`.
  - Authorize with `InstalledAppFlow.from_client_secrets_file('credentials.json', SCOPES).run_local_server(port=0)`.
  - Store the result in `token.json` and call `creds.refresh(Request())` when it expires.
  - https://developers.google.com/workspace/gmail/api/quickstart/python
- **Scopes (by Google's classification):**
  - `gmail.readonly`, `gmail.compose`, `gmail.modify`, `gmail.metadata` and `https://mail.google.com/` are **Restricted**.
  - `gmail.send` is Sensitive.
  - `gmail.labels` is Non-sensitive.
  - `gmail.modify` alone covers reading, labeling, drafts and sending. The narrowest workable set is `gmail.readonly` + `gmail.compose` (drafts and send) + `gmail.labels`.
  - https://developers.google.com/workspace/gmail/api/auth/scopes
- **7-day refresh-token expiry:**
  - Google's docs: "external user type and a publishing status of 'Testing' is issued a refresh token expiring in 7 days".
  - Other ways a token dies: 6 months unused, more than 100 refresh tokens per account per client, a password change while Gmail scopes are granted, or the user revoking access.
  - https://developers.google.com/identity/protocols/oauth2
  - **Fix:** set the consent screen to **In production**. A personal-use app (not shared, or fewer than 100 users you know) doesn't need verification; users click through the "unverified app" warning. https://support.google.com/cloud/answer/13464323
  - Unverified apps are capped at 100 new users. https://support.google.com/cloud/answer/7454865
- **Polling vs push:**
  - **Polling:** `users.history.list(startHistoryId=…, historyTypes=…, labelId=…)`. A 404 means the history ID is too old, so do a full sync. History is kept "typically… at least one week". https://developers.google.com/workspace/gmail/api/guides/sync
  - **Push:** needs a Pub/Sub topic with publish rights granted to `gmail-api-push@system.gserviceaccount.com`, then `users.watch{topicName,labelIds,labelFilterBehavior}`. Re-run watch **at least every 7 days** (daily is recommended). Notifications carry `{emailAddress, historyId}`, at most 1 event per second per user, and can be dropped, so keep fallback polling. A pull subscription avoids needing a public webhook, but a GCP project is still required. https://developers.google.com/workspace/gmail/api/guides/push
  - For a local app, `history.list` polling every few minutes is simpler.
- **Sending:**
  - Build an `email.message.EmailMessage`, encode with `base64.urlsafe_b64encode(msg.as_bytes()).decode()`, and send `{"raw": …}` to `messages.send` or `drafts.create`.
  - To reply in a thread, set `threadId` and the `In-Reply-To` and `References` headers, and keep the same Subject. https://developers.google.com/workspace/gmail/api/guides/sending
  - Messages up to 35 MB via multipart or resumable upload (`/upload/gmail/v1/users/me/messages/send`). https://developers.google.com/workspace/gmail/api/guides/uploads
- **Quota:** 6,000 units per user per minute. `messages.send` and `drafts.send` cost 100 units each. https://developers.google.com/workspace/gmail/api/reference/quota

## 5. Claude Code headless mode and the Agent SDK

Sources: https://code.claude.com/docs/en/headless and https://code.claude.com/docs/en/cli-reference

- **Basic call:** `claude -p "…" --output-format text|json|stream-json`
  - `stream-json` needs `--verbose`. Add `--include-partial-messages` for token deltas.
  - Stdin is capped at 10 MB. Exits non-zero on failure. SIGTERM exits with code 143.
- **Flags:**
  - Model and limits: `--model <alias|id>`, `--fallback-model`, `--max-turns N`, `--max-budget-usd X`
  - Tools: `--allowedTools "Read,Bash(git diff *)"`, `--disallowedTools`, `--tools`
  - System prompt: `--append-system-prompt[-file]`, `--system-prompt[-file]`
  - Permissions: `--permission-mode acceptEdits|auto|dontAsk|plan|bypassPermissions`, `--permission-prompts none` (v2.1.259+)
  - Config: `--mcp-config`, `--settings`, `--add-dir`
  - Sessions: `--resume <id>`, `--continue`, `--no-session-persistence`
- **`--bare`:**
  - Skips hooks, skills, plugins, MCP, CLAUDE.md and auto-memory. The docs recommend it for scripts; it will become the default for `-p`.
  - It needs `ANTHROPIC_API_KEY` because it ignores the OAuth/keychain login.
- **Structured output:**
  - Use `--output-format json --json-schema '<schema>'`. The result lands in `.structured_output`.
  - An invalid schema is a hard error (v2.1.205+). `format` is accepted but not enforced.
- **JSON result fields:** `type, subtype` (`success`, `error_max_turns`, `error_max_budget_usd`, `error_during_execution`, `error_max_structured_output_retries`), `is_error, result, structured_output, session_id, num_turns, duration_ms, duration_api_ms, total_cost_usd, usage{input_tokens,output_tokens,cache_creation_input_tokens,cache_read_input_tokens}, modelUsage, permission_denials`.
  - `total_cost_usd` is a **client-side estimate**.
  - `usage` leaves out subagent tokens; `modelUsage` includes them.
  - A resumed session reports the cumulative spend.
  - https://code.claude.com/docs/en/agent-sdk/cost-tracking
- **Python SDK:**
  - Package `claude-agent-sdk` (v0.2.160 as of 2026-09-25). Needs Python 3.10+. The CLI is bundled; override it with `cli_path`. https://pypi.org/project/claude-agent-sdk/
  - Usage: `async for m in query(prompt=..., options=ClaudeAgentOptions(...))`. Use `ClaudeSDKClient` for multi-turn sessions or interrupts.
  - Options: `system_prompt` (a string or `{"type":"preset","preset":"claude_code","append":...}`), `allowed_tools, disallowed_tools, permission_mode, max_turns, max_budget_usd, model, cwd, mcp_servers, setting_sources, env, cli_path, output_format={"type":"json_schema","schema":...}`
  - `ResultMessage` fields: `result, is_error, subtype, structured_output, num_turns, duration_ms, total_cost_usd, usage, model_usage, session_id`
  - Schemas are validated as draft-07. Treat `success` without `structured_output` as a failure.
  - https://code.claude.com/docs/en/agent-sdk/python and https://code.claude.com/docs/en/agent-sdk/structured-outputs

## 6. Local model serving (OpenAI-compatible)

### mlx_lm.server
- **Start:** `mlx_lm.server --model <hf_repo|path>` (default `127.0.0.1:8080`)
- **Flags:** `--host --port --adapter-path --draft-model --num-draft-tokens --trust-remote-code --chat-template --temp --top-p --top-k --min-p --max-tokens --decode-concurrency --prompt-concurrency --prompt-cache-size --prompt-cache-bytes --kv-bits --pipeline --allowed-origins`
- **Endpoints:** `POST /v1/completions`, `POST /v1/chat/completions`, `GET /v1/models`, `GET /health`
- **One model at a time per process.** The request's `model` field hot-swaps: `ModelProvider._load` calls `reset()` and `mx.clear_cache()` and drops the old model. (Source: server.py)
- **No `response_format` / json_schema support** (none in server.py). Use prompt-plus-validate-and-retry, or Outlines.
- **Also supported:** `stream_options.include_usage`, `logprobs`/`top_logprobs`, and tools.
- Its docs say it is "not recommended for production".
- https://github.com/ml-explore/mlx-lm/blob/main/mlx_lm/SERVER.md

### llama.cpp `llama-server`
- **Flags:** `-m` or `-hf user/repo[:quant]`, `-c`, `-ngl`, `--host`, `--port`, `-np/--parallel`, `--jinja` (on by default), `--metrics`
- **Structured output:**
  - OpenAI `response_format` accepts `{"type":"json_object"}` or `{"type":"json_schema","schema":{…}}`.
  - The native `/completion` accepts `json_schema` and `grammar` (GBNF). Server-wide defaults: `--json-schema[-file]`, `--grammar[-file]`.
- **Throughput:** each response has a `timings` object with `prompt_per_second` and `predicted_per_second`.
- **Other endpoints:** `/health, /metrics, /props, /slots`
- **Router mode:** start with no model; `--models-dir`, `--models-max N` (default 4). It spawns child processes, one per model, so measure memory per child.
- https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md

### Ollama
- **Structured output:** `"format": "json"` or `"format": <JSON schema>` on `/api/chat` and `/api/generate`. `/v1/chat/completions` accepts `response_format`. Tips: temperature 0 and include the schema in the prompt. https://docs.ollama.com/capabilities/structured-outputs
- **Timing:** `eval_count` and `eval_duration` (nanoseconds), so tok/s = `eval_count / eval_duration * 1e9`.
- **Memory:** `keep_alive` controls how long a model stays loaded ("5m", or 0 to unload). https://docs.ollama.com/api/generate

### LM Studio
- **Server:** `lms server start`, port `1234`.
- **Structured output:** `response_format:{type:"json_schema",json_schema:{name,strict,schema}}`. GGUF models are constrained through llama.cpp grammar; MLX models through Outlines. Models under 7B may do poorly. https://lmstudio.ai/docs/developer/openai-compat/structured-output
- **Stats:** `/api/v0/chat/completions` returns `stats{tokens_per_second,time_to_first_token,generation_time,stop_reason}`. https://lmstudio.ai/docs/developer/rest/endpoints
- **Model loading:** JIT loading with idle TTL (default 60 min, `ttl` per request). Auto-evict keeps only one JIT-loaded model; manually loaded models can run side by side. https://lmstudio.ai/docs/developer/core/ttl-and-auto-evict

### Measuring memory on macOS
- `psutil.Process().memory_info()` on macOS gives `rss, vms, pfaults, pageins`, and `memory_full_info()` adds `uss`. There is **no phys_footprint** field. https://psutil.readthedocs.io/
- RSS can't see Metal/unified-memory buffers. Example: a 2 GiB MLX array showed RSS 0.03 GiB vs footprint 2.02 GiB. https://github.com/unxmaal/localharness/pull/243
- `mx.get_peak_memory()` can also undercount (46 GB reported vs 110 GB actual). https://github.com/ml-explore/mlx/issues/3896
- **Use phys_footprint instead:** `footprint <pid>` (CLI), Activity Monitor's Memory column, or `proc_pid_rusage(RUSAGE_INFO_V2).ri_phys_footprint` via ctypes. Watch `vm_stat` swap and compressor as early warnings.

## 8. Frontend

- **Globe:**
  - `react-globe.gl` (MIT, three.js). Default textures load from the unpkg CDN, so self-host `globeImageUrl`/`bumpImageUrl` for offline use. Arcs animate with `arcDashLength/arcDashGap/arcDashAnimateTime`. Needs WebGL, no SSR. https://github.com/vasturiano/react-globe.gl
  - Lighter offline option: `d3-geo` (`geoOrthographic`, `geoPath`) plus `topojson-client` plus the npm package `world-atlas` (`countries-110m.json` / `50m` / `10m`; Natural Earth, ISC). The repo was archived in 2023, but the data is stable. https://github.com/topojson/world-atlas
- **Agent graph:**
  - `@xyflow/react` edges take an `animated` prop (dashed line).
  - For particles, write a custom edge: `getBezierPath()` plus `<BaseEdge/>` plus a `<circle>` with `<animateMotion path={edgePath} />`. Alternatively, use the Web Animations API with `offsetPath`/`offsetDistance`.
  - https://reactflow.dev/examples/edges/animating-edges
- **Animation:** Framer Motion is now **Motion**. Install `motion` and import from `motion/react`; `framer-motion` is no longer maintained. https://motion.dev/docs/react-upgrade-guide
- **Charts:**
  - Recharts is declarative (`<LineChart><XAxis/>…`) and quick for standard dashboards, but large (about 290 KB).
  - visx is low-level D3 primitives: most flexible, but 2–3× the build effort.
  - https://www.pkgpulse.com/guides/recharts-vs-chartjs-vs-nivo-vs-visx-react-charting-2026 and https://blog.logrocket.com/best-react-chart-libraries-2026/
- **Fonts:** `npm i @fontsource-variable/inter`, then `import "@fontsource-variable/inter"`. Fonts are bundled and self-hosted with no CDN calls. Static weights: `@fontsource/inter/400.css`. https://fontsource.org/docs/getting-started/install
- **Server-sent events:**
  - FastAPI **0.135.0+** has native SSE: `from fastapi.sse import EventSourceResponse, ServerSentEvent`. It sends a keep-alive ping every 15 s and sets `Cache-Control: no-cache` and `X-Accel-Buffering: no`. https://fastapi.tiangolo.com/tutorial/server-sent-events/
  - Older versions: `sse-starlette` `EventSourceResponse` (yield `{event,data,id,retry}`; `ping` default 15 s; `send_timeout`; check `await request.is_disconnected()`). https://github.com/sysid/sse-starlette
  - SSE is enough for one-way dashboard updates. Use WebSocket only for two-way control.

## 9. macOS

- **LaunchAgent:** put it at `~/Library/LaunchAgents/<label>.plist`. From `man launchd.plist`:
  - `Label` and `ProgramArguments` (array) are required.
  - `RunAtLoad` defaults to false.
  - `KeepAlive` is a bool or a dict of `SuccessfulExit`/`Crashed`/`PathState`, and it implies RunAtLoad. `NetworkState` no longer works.
  - `StandardOutPath` / `StandardErrorPath` files are created if missing.
  - Also: `WorkingDirectory`, `EnvironmentVariables` (launchd doesn't inherit your shell PATH, so set it explicitly).
  - `ThrottleInterval` defaults to 10 s between respawns.
  - `StartInterval` / `StartCalendarInterval`: unlike cron, a missed run fires on wake, and several missed runs are merged into one.
  - `ProcessType` = Background / Standard / Adaptive / Interactive.
  - Load with `launchctl bootstrap gui/$(id -u) <plist>`; unload with `launchctl bootout …`.
  - Online copy: https://keith.github.io/xcode-man-pages/launchd.plist.5.html
- **Keeping the Mac awake (`caffeinate`):**
  - `-i` prevents idle sleep; `-s` prevents system sleep (**only on AC power**); `-d` keeps the display on; `-m` keeps the disk on; `-u` declares the user active.
  - `-t secs` sets a timeout; `-w pid` holds the assertion until that process exits. `caffeinate -is <cmd>` holds it for the command's lifetime.
  - Closing a laptop lid still sleeps the Mac unless it is in clamshell mode.
- **`pmset`:**
  - `pmset -c sleep 0` (`-a` all, `-b` battery, `-c` charger).
  - Scheduled wake: `pmset repeat wakeorpoweron MTWRFSU 08:00:00` (only one repeating on/off pair allowed).
  - Check what is holding the Mac awake: `pmset -g assertions`. View a sleep/wake history: `pmset -g log`.
  - https://keith.github.io/xcode-man-pages/pmset.1.html
- **Notifications:**
  - `osascript -e 'display notification "msg" with title "Agent HQ" subtitle "…" sound name "Frog"'`. Notifications are attributed to Script Editor/osascript and can't open a URL when clicked. https://developer.apple.com/library/archive/documentation/LanguagesUtilities/Conceptual/MacAutomationScriptingGuide/DisplayNotifications.html
  - `brew install terminal-notifier`, then `-title -subtitle -message -sound -open URL -execute CMD -group ID`. Version 3.x uses the UserNotifications API. `-diagnose` checks notification permission. https://github.com/julienXX/terminal-notifier
